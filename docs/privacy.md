# Privacy

Local token analysis, prompt optimization, repository indexing, retrieval and analytics make no model-provider requests. Dashboard assets are local; there is no application telemetry or hosted account. Build/dev scripts disable Next.js telemetry. External requests require configuration opt-in and explicit operation consent.

Default state is `.contextpilot/state.sqlite`. Managed session storage is enabled by default because sessions and recovery checkpoints intentionally retain redacted task context. Set `managed_session_storage:false` to prevent new managed session writes; existing records remain available for inspection/export/deletion. A project cannot override the global storage disable switch. Local state is not encrypted at rest.

Optimization prompt-body logging is disabled by default. Setting `prompt_logging:true` explicitly stores redacted original and optimized prompts locally. Event retention (default 30 days) covers usage, optimization, compaction, evaluation and optional prompt-log metadata. Managed sessions and recovery snapshots persist until explicit deletion to avoid silently removing recovery information. `clear-usage --yes` removes retained event data; session deletion removes associated owned recovery records. Exports/backups may contain private context; you control retention of those files.

Repository caches store filenames, hashes, language labels, symbol names and import relationships under the selected repository's `.contextpilot`; they do not cache full source bodies. Current files and hashes determine retrieval. Secret/private-key/binary/generated sources, source symlinks and ignore patterns are excluded. Symbol extraction is heuristic, and best-effort exclusions/redaction cannot prove arbitrary source contains no sensitive information. Attached excerpts are intentionally persisted as managed session context. Source replacements/deletions preserve a recovery snapshot before removing stale attached content.

API credentials can live in backend environment variables or the native OS vault (macOS Keychain, Windows Credential Manager, Linux Secret Service). Environment values take precedence. There is no plaintext credential fallback, key-bearing command argument or dashboard key field. Provider discovery reports environment presence and `vault_status:not_queried` without opening a vault. Vault access can require OS approval during an explicitly requested credential/provider operation. An explicitly opted-in macOS Apple Silicon integration check successfully created, read and deleted a unique nonsecret probe entry, then confirmed its absence. It never read existing provider credentials. Routine tests remain mock-based; Linux/Windows and Intel macOS vault runtime behavior is unverified.

Provider generate/deep/count operations send the redacted selected text to the named provider. Counting also sends content externally, although it does not generate a response. No entire repository is automatically uploaded. Provider credentials and upstream error bodies are never returned to dashboard clients or written to application logs. Redaction does not replace checking source privacy. See [provider integrations](provider-integrations.md) for the exact interfaces.

The HTTP server binds loopback, validates Host/Origin and authenticates every API route. Treat the dashboard token and data directory as private. Unix owner-only permissions are applied to private state and exports; Windows data uses an owner-protected directory ACL. These controls do not protect against a compromised account or local administrator.
