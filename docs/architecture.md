# Architecture

`contextpilot-core` owns text tokenization, conservative optimization, budgets, checkpoints, pricing, repository indexing and efficiency instructions. `contextpilot-providers` owns consent-gated text generation/counting and native vault access. `contextpilot-app` exposes CLI and authenticated Axum API over the same engine and SQLite store. Next.js produces a static export served by the Rust process; Node is a build dependency, not a runtime server.

SQLite schema version 2 uses typed JSON records keyed by kind/id, settings, integrity-checked recovery snapshots and indexed event metadata. Migrations preserve prior state and reject databases newer than the application. WAL, bounded busy timeout and immediate transactions coordinate session appends, compaction and source replacement. API database work runs on blocking workers with a mutex; external network calls do not hold that database mutex. The session revision prevents an external generation from silently appending to a changed session.

Bundled `tiktoken-rs` vocabularies provide exact text-encoding counts for explicitly mapped OpenAI models (`o200k_base` or `cl100k_base`). This is not billable-request usage: framing, tools, images and provider-internal tokens are excluded. Unknown models/providers fall back to labeled `ceil(UTF8 bytes / 4)` estimates. Anthropic's optional remote count is separately labeled `provider_counted`; actual generation usage is `provider_reported`. UI estimation calls the backend rather than duplicating token arithmetic.

The repository engine traverses ignored-aware regular text files without following source symlinks. Its metadata-only JSON cache stores current content hashes, language extensions, heuristic symbol declarations and import/dependency relationships. Deterministic ranking weighs path/symbol/text matches and dependencies. Current inventory/hashes invalidate cache entries and previously attached source versions. Parsable Rust selects complete containing functions through `syn`; other/unparseable languages retain complete files with explicit fallback notes. Scans are capped at 20,000 files / 128 MiB. Excerpts retain paths and line ranges; configured aggregate retrieval limits mark omissions explicitly instead of silently truncating. Parsing is heuristic, not a complete compiler AST, semantic embedding index or language server.

Global configuration supplies defaults. Registered projects carry partial overrides, and linked sessions use their effective project settings. Global external-access/storage switches remain upper bounds. Context capacity resolves from a session override, effective configuration, then selected user-supplied model metadata. Response reserve and configured system/tool overhead contribute to budget state. Models and prices require provenance/dates; no current commercial limits or rates are bundled.

`tokens DIRECTORY` counts every eligible full UTF-8 file with explicit coverage and no source body in its result; oversized aggregate scans fail without a partial total. Directory tokenization, CLI retrieval and indexing use effective project settings for an exact registered canonical root, otherwise global configuration. `profile.max_files` and aggregate `max_file_tokens` are enforced for CLI/project retrieval; report size is enforced for inline CLI reports with full file export available. The owned tool-output processor uses the configured character target conservatively, reducing recognized routine progress while preserving all other redacted content and exit status, even above target. Verbosity, external tool-output targets, subagent concurrency and verification preference are exported instructions; the application does not orchestrate external tools/subagents or guarantee their behavior. Tool compaction uses conservative recognized compiler-progress reduction rather than arbitrary character truncation. No external agent state is inspected or rewritten.

Schema contracts are generated from the Rust domain/serde types through `contextpilot schema` and authenticated `/api/v1/schema`. These JSON Schemas are not a complete OpenAPI endpoint specification. Analytics separate estimates, provider/imported usage, dated monetary estimates and supplied evaluation evidence; they do not infer causal savings from smaller prompts alone.
