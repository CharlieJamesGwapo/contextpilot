# Managed sessions and recovery

Create a session with objective, requirements, constraints, unresolved issues and next actions. Categorized messages preserve decisions, failures, verification evidence, tool output and assistant context. Known secret patterns are redacted before persistence. Managed storage must be enabled; this local recovery content is intentionally retained until explicit deletion.

`compact --session ID --preview` produces a checkpoint and source revision without writing. Commit with `--commit --revision REV`; intervening changes reject the stale preview. Manual checkpoint creation applies the same recoverable compaction. Full pre-compaction state and structured continuation are saved in one SQLite transaction. Restore first snapshots the current state, then restores the checkpoint's source state, preserving later additions through a separate recovery record.

The deterministic transformation removes safe adjacent duplicate context and summarizes ten or more recognized routine Rust compiler-progress lines in messages explicitly categorized `tool`. Errors, stack traces, commands, exits, test results, unique paths and unrecognized content remain. Important categories and safety repetition are preserved. It does not infer success, resolve contradictions or summarize arbitrary critical prose. Source excerpts carry hashes/line ranges; attaching refreshed source snapshots the prior session before removing changed/deleted versions. Unchanged excerpts are reused instead of repeatedly appended. Budget-omitted excerpts remain visibly marked.

Budgets use the configured text tokenizer, known session/config/model capacity, response reserve and explicit system/tool overhead. Unknown capacity stays unknown. At emergency thresholds, owned generation is rejected and optional context growth is limited. Automatic compaction is opt-in on managed appends and uses the configured auto threshold (85% by default). Full original content remains recoverable; automatic processing does not mutate external conversations.

Checkpoint schema version 1 preserves objectives, requirements, constraints, decisions, changed-file references, verified results, unresolved issues, next actions, recovery references and approval boundaries, plus source revision/usage and integrity hashes. Empty structured references are not evidence that no files changed. Hashes detect corruption rather than malicious local tampering.

`handoff --session ID NEW_DIRECTORY` exports `checkpoint.json`, `continuation.md` and `AGENT-INSTRUCTIONS.md`. It does not alter an external assistant's private state or automatically continue another product's session. The separate `tool-output` CLI/API processor applies the configured character target to owned output using the same conservative progress reduction and preserves complete redacted output for optional export. Efficiency settings for verbosity, external tool-output targets, subagent concurrency and verification become guidance in exported instructions; they are not enforcement hooks in an external agent.
